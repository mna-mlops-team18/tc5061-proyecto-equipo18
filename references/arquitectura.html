Arquitectura del proyecto MiBici - equipo 18

De los CSV del portal al registro de experimentos. Cada paso es un comando del repositorio; los datos no entran a Git, su version si.
1 - Fuente

Portal de datos abiertos MiBici

  • 24 CSV mensuales de viajes (oct-2024 a sep-2026): 9.04 millones de viajes
  • Nomenclatura 2026-09: coordenadas y capacidad de 484 estaciones (470 activas)
  • Formatos variables entre anios (codificacion, comillas, fechas)
HTTPSCSV
2 - Ingesta y versionado

dataset.py ingest - verify

  • Descarga sin pasos manuales, con reintentos
  • Detecta codificacion, delimitador y formato de fecha por archivo
  • Normaliza columnas; descarta usuario, genero y anio de nacimiento
  • verify recalcula hashes y los compara con el manifiesto
requestspandashashlibtyper
3 - Almacenamiento

Datos locales + manifiesto en Git

  • data/raw/ CSV originales
  • data/processed/ un Parquet (zstd) por mes + estaciones
  • data/ esta en .gitignore
references/manifiesto_datos.json - registros y SHA-256 de cada archivo -> data_version, versionado en Git
ParquetpyarrowGit
4 - Procesamiento

features.py

  • Filtros de limpieza (duracion 1 min-4 h, estaciones conocidas)
  • Malla estacion-hora con ceros; bloques de 3 h para P2
  • Calendario y festivos; rezagos y medias solo con el pasado
  • Salida: conjuntos P1 - P2 - P3 + features_meta.json
pandasnumpypytest (sin fuga)
5 - Entrenamiento y registro

modeling/ + MLflow

  • comun.py + un modulo por pregunta (P1 regresion, P2 clasificacion, P3 clustering)
  • Baseline y candidato; train.py o mlflow run (MLproject)
MLflow Tracking - mlflow.db + mlruns/: parametros (fechas, data_version, semilla, hiperparametros), metricas entrenamiento_/validacion_/prueba_, etiquetas (equipo, pregunta, rol, git_commit), artefactos y modelo
